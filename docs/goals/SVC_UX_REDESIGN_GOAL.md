# svc-dashboard 主界面 UX 重构（视觉评审+用户拍板）— 完整任务目标

## 一、用户拍板（必做）

**顶部页签与底部导航重复——去掉顶部页签区**，导航只留底部页签栏。
底部加「日志」页签 → 五页签：概要 / Goal / 服务 / 模型 / 日志。

## 二、概要页重构（先摘要后事件）

1. **总体状态卡**（首屏第一眼）：大字「✅ 全部正常 / ⚠ 有告警 N」+
   数据新鲜度（更新时间超过 2× 刷新周期 → 黄标「数据过期」）
2. **关键指标行**（紧凑 2×2 卡片）：正常服务 X/Y · 跑动中 Goal N · 暂停/异常 N · 未处理告警 N
3. **「需要处理」区**：只列高优先级（暂停 goal/挂死/完成待查看），每条带操作
   （复制 resume 命令/查看详情）
4. **最近活动**：3-5 条摘要事件（一行一条：图标+类型+相对时间），点击进日志页；
   **不再整屏日志**

## 三、日志页强化

- 事件条目压缩：第一行 状态图标+类型+相对时间，第二行一句话摘要；
  PID/文件名/原始文本**默认折叠**点开看
- 筛选 chips：状态（成功/告警/失败/恢复）+ 来源（watchdog/完成/commit）+
  时间（24h/3d/7d/全部，**默认 24h**）
- 同 goal 循环事件折叠「循环 ×N」可展开（降噪 019feb87 类刷屏）

## 四、视觉统一

- 语义色规约：红=严重 / 黄=关注 / 绿=正常 / 灰=历史 / 蓝=交互；
  状态用 图标+文字 双通道（不只靠颜色）
- 顶部状态摘要对比度提到 WCAG AA（4.5:1）；字号体系：状态数字 20-28px /
  正文 14-15px / 辅助 12px
- 语言统一：面板日文界面 → 核心操作统一日文，技术原文（watchdog/goal id）做次级
- 文案：「21 個の待受ポート」→「サービス 21」类统一表达

## 五、告警中心（轻量版）

- 概要页「需要处理」即告警中心；未处理数量徽章显示在底部「概要」页签图标上（红点+数字）
- 每条告警可「忽略」（localStorage 记已忽略，同 goal+类型不再提醒）

## 六、布局技术修正

- 日志/滚动容器改内部滚动 + padding-bottom 含 safe-area+页签栏高度——
  最后一条完整可见（上一轮反馈的遮挡问题，一并修）
- 顶部区域压缩：标题行+状态摘要合并紧凑化（去掉页签区后自然省出）

## 七、验收

1. 顶部页签区移除；底部五页签（含日志）；概要页 3 秒判断系统状态（改造前后截图对比）
2. 概要页结构：状态卡+指标 2×2+需要处理+最近活动（无整屏日志）
3. 日志页折叠/筛选/时间范围默认 24h/循环折叠 全部可用
4. 底部页签未处理徽章显示；忽略功能生效
5. 390x844 与桌面 1280 双视口截图；对比度抽查两处达标
6. curl 200；commit+push（中文）

## 八、边界

- 纯标准库单文件；只动 svc-dashboard 仓库；改前备份 dashboard.py.bak-<date>
- 桌面 ≥768px 布局保持现有（媒体查询分支），移动端重构不影响桌面
