# Mikata UI 视觉规范

本规范适用于在线仪表盘与静态快照。参考 AWS 首页的信息组织方式：清楚分区、直接层级、细边框和克制的强调色；保留 Mikata 的深色运维工作台定位，不复制 AWS 品牌组件。

## 视觉原则

- **先让数据说话**：关键数值、状态和时间优先，装饰只帮助识别和分组。
- **用结构代替效果**：依靠标题层级、对齐、留白和分隔线建立层次，不使用渐变、霓虹、玻璃效果或发光阴影作为普通组件底色。
- **一个主强调色**：暖橙用于主要动作和当前选择；蓝色用于链接与可交互信息；绿、黄、红只表达运行状态。
- **表面保持克制**：页面底色、面板底色和浮层底色最多三级；统一细边框和紧凑圆角，不让每行信息都成为独立卡片。
- **数据字体有职责**：等宽字体用于指标、端口、时间和代码；正文保持系统无衬线字体。

## Token

| Token | 深色值 | 用途 |
|---|---|---|
| 页面底色 | `#0b0d12` | 主背景 |
| 面板底色 | `#11151c` | 面板与主要容器 |
| 次级底色 | `#171c24` | 输入、悬停、次级区域 |
| 主文字 | `#e8edf2` | 标题与关键内容 |
| 次级文字 | `#9aa6b2` | 描述与标签 |
| 细分隔线 | `rgba(180,195,210,.14)` | 面板、行和表格分隔 |
| 主强调 | `#ff9900` | 主操作与当前选择 |
| 链接强调 | `#7db8e8` | 链接与导航 |
| 圆角 | 8px | 面板与控件；状态点使用圆形 |
| 间距 | 4 / 8 / 12 / 16 / 24px | 紧凑、组件、区块、页面节奏 |

浅色主题使用同一语义映射：白色面板、浅灰页面底色、深色正文和更深的边框；状态色必须保持语义一致。

## 组件规则

- **页面标题**：标题 17–20px、600–700 字重；辅助说明 12px，和标题分开，不塞进同一行。
- **页面与面板**：各页面外层使用与首页一致的面板底色、1px 边框和 8px 圆角；列表、指标和图表用留白与细线分组。
- **按钮**：主操作使用强调色实底；次操作使用透明底和细边框；低频动作使用文字按钮。禁用渐变和发光投影。
- **主题切换**：放在顶栏，以单击在深色与浅色间切换；保存为显式偏好，图标与辅助标签始终说明下一步动作。
- **子导航与筛选项**：子导航以文字和底部细线表达选中状态；筛选项使用小圆角控件，并保证两种主题中的文字可读。
- **状态**：绿=正常、黄=关注、红=异常、灰=未知/停止。状态颜色不能用于纯装饰。
- **表格与活动流**：列标题低对比，行间用细线；整行悬停反馈轻微，不套额外卡片。
- **活动日志表格**：跟随容器宽度，窄屏隐藏次要列并截断长内容；不出现内嵌横向滚动条。
- **图表**：细网格、清晰图例和真实数据色；不添加无数据依据的光晕或视觉装饰。
- **移动端**：保持单列阅读顺序，关键操作触控区至少 40px；页面底部避开固定导航，不产生横向溢出。

## 验收约束

新增或修改组件时复用本规范及 `static/app.css` 中的语义变量。页面级差异只通过局部布局规则表达，不另外引入一套按钮、圆角、阴影或状态色。验收桌面 1440×900 和手机 390×844，检查控制台异常、横向溢出、主要操作和当前页面功能。
