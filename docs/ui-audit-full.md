# svc-dashboard 整站 UI 审计（双视口全页走查）

- 审计日期：2026-08-15
- 审计对象：`dashboard.py`（7580 行，单文件内嵌 HTML/CSS/JS）
- 视口：桌面 1280×900 / 移动 390×844
- 证据：`screenshots/audit/` 27 张双视口分段滚动截图 + 源码行号
- 审计标准：iOS Liquid Glass 设计语言、桌面横向多列 / 移动单列+悬浮导航、禁 emoji（内联 SVG）、禁原生 alert/select、状态色语义（红=严重 黄=关注 绿=正常 灰=历史 蓝=交互）、双端一等公民

---

## 1. 总评

**病根一句话：移动端已按"App 化运维中枢"打磨到位，桌面端只是同一套纵向内容流的"拉伸投屏"——分类条过滤代替不了页面架构，宽度利用率、信息密度与可达性（日志/模型页桌面无入口）系统性缺位。**

全站共性问题（跨页反复出现）：

1. **桌面宽度利用不足 / 半宽截断**：概览页 Web 服务卡与 Goal 卡合计仅占约 2/3 宽，右侧留白；Goal 卡片网格第二行 2 卡后 1/3 宽空白（desktop-s0/s2）。
2. **移动端底部内容被悬浮导航遮挡**：概览"最近活动"、日志列表末条、服务列表末卡、工具页端口列表尾行，均被 64px 悬浮胶囊栏压住（`#track > .pg` 的 padding-bottom 计算，dashboard.py:3439）。截图反复捕捉到遮挡态。
3. **状态色语义不完整**：指标数值几乎全为黑字（CPU 100%、内存 93% 无警示色）；Swap 100% 硬编码绿色（:5766）；日志筛选 chips（成功/告警/失败/恢复）无对应状态色；服务行无运行状态色。
4. **加载态弱**："读取中…/加载中…"纯文字，无 spinner/骨架屏一致性（模型页有骨架，概览 Web 服务卡没有）；桌面 Goal 页整页只有两行字 + 726px 空白。
5. **按钮/胶囊三套风格混用**：顶栏导航胶囊（白底描边）、分类 chips（黑底白字选中）、卡片内文字链（"▸ 详情"蓝色文字）三套交互语言并存，层级弱。
